# Collecte privée du laboratoire

Overlay séparé : `kubectl kustomize deploy/kubernetes/monitoring`. Il ne remplace pas les déploiements de la base. Namespace `ddostester-lab`, CNI appliquant NetworkPolicy et StorageClass par défaut nécessaires. Aucune exposition NodePort/LoadBalancer ; accès par `kubectl port-forward --address 127.0.0.1 service/lab-grafana 18584:3000` avec contexte explicitement vérifié.

Versions vérifiées le 14 octobre 2026 auprès des releases officielles et du registre : Prometheus **3.15.0**, Grafana **13.2.4**, index multiarchitecture épinglés par digest dans workloads.yaml (amd64/arm64 présents). Le déploiement Linux monitoring-01 est disponible : deux scrapes up, login admin, refus anonyme, datasource et deux dashboards vérifiés par un Job isolé. La règle d’alerte est testée hors ligne, chargée et saine. La requête historique de référence est identique après recréation du Pod Prometheus, avec le même PVC. Une interruption de scrape HTTP 404 provoque down/pending/firing ; après restauration, up et inactive sont vérifiés. La persistance Grafana est vérifiée par une annotation unique conservée après recréation du Pod sur le même PVC. Le corpus réseau et le rendu visuel des panneaux restent à vérifier. Un rendu seul ne prouve pas le fonctionnement du cluster.

Le contrôle dédié et Prometheus sont collectés toutes les 15 secondes. Le nouvel overlay ajoute `lab-target-receipts`, toutes les 5 secondes, timeout 3 secondes et limite de 5 000 échantillons. Il nécessite l’image telemetry exposant `/metrics` en plus du JSON existant. La sonde reste interrogée via son API authentifiée ; aucune mesure indépendante de protection n’est inventée. Les dashboards Run/Resilience sont repris du dépôt ; les panneaux sans observations restent vides. Une recette ultérieure doit vérifier chaque série réellement présente et compléter les panneaux de flotte.

Rétention configurée dans `storage.tsdb.retention` : 7 jours ou 1 GB de blocs, avec PVC 2 Gi. Le WAL et le head nécessitent de la marge ; ce paramètre n'est pas un quota disque total. Avec local-path, la demande PVC ne garantit pas un quota physique : surveiller le disque hôte et tester la saturation. Grafana possède son propre PVC 512 Mi. Les données sont séparées de Grafana/Prometheus déjà présents sur le VPS.

Créer le Secret `lab-monitoring-credentials` avec la clé `admin-password`, aléatoire et privé, avant déploiement ; ne pas le committer ni passer sa valeur dans des arguments visibles. Login `lab-admin`, accès anonyme et inscription désactivés. Aucun plugin externe ou rapport d'usage requis. Racines read-only, utilisateurs non-root, seccomp RuntimeDefault, capabilities supprimées, tokens SA non montés ; limites cumulées 400m CPU / 768 Mi RAM. Préserver les budgets de la sonde et réévaluer la contention pendant les recettes.

Les politiques ajoutent Prometheus → contrôle, Prometheus → reçus cible sur 9101 et Grafana → Prometheus ; le refus réseau et DNS de la base restent requis. Comme NetworkPolicy filtre aux couches L3/L4, Prometheus atteint le port HTTP du contrôle entier, pas seulement `/metrics` ; les autres routes conservent leur authentification applicative. Aucun accès à PostgreSQL ni au port applicatif 8080 de la cible n’est ajouté pour Prometheus.

Provisioning datasource UID `prometheus`, folder Private lab, dashboards non modifiables. Les copies 01-run.json/02-resilience.json doivent rester synchronisées avec deploy/monitoring/grafana/dashboards ; elles sont embarquées par ConfigMap. Un changement de fichiers montés par subPath nécessite de recréer le Pod, ce que les noms ConfigMap Kustomize versionnés provoquent par changement du template.

Validation requise avant déclaration opérationnelle : `promtool check config`, validation serveur des manifests et Pod Security, PVC Bound, Pods Ready, digest imageID attendu, scrape `up=1`, séries et panneaux vérifiés via API, login Grafana, absence d'exposition publique, refus réseau, redémarrage avec conservation des mesures et test d'alerte de collecte interrompue. Aucun succès de ces contrôles n'est déduit du seul rendu.

Sources officielles : [configuration Prometheus](https://prometheus.io/docs/prometheus/latest/configuration/configuration/), [stockage et rétention](https://prometheus.io/docs/prometheus/latest/storage/), [image Grafana](https://grafana.com/docs/grafana/latest/setup-grafana/configure-docker/), [provisioning Grafana](https://grafana.com/docs/grafana/latest/administration/provisioning/).

La règle `LabControlScrapeUnavailable` couvre un scrape nul ou absent pendant une minute. `promtool test rules lab.rules.test.yml` valide les cas up, down et série absente ; le runner exige un tmpfs /tmp borné pour son stockage de test. Aucun Alertmanager/destinataire externe n’est configuré : une alerte locale ne constitue pas une notification livrée.

Recette de persistance : `scripts/operations/verify-grafana-persistence.mjs` exécuté dans un Job restreint, phases create/verify/cleanup, identité d’annotation exacte et nonce distinct. Les [annotations Grafana](https://grafana.com/docs/grafana/latest/developer-resources/api-reference/http-api/api-legacy/annotations/) sont enregistrées en base ; leur API legacy reste disponible en v13, avec dépréciation. Cette recette prouve une donnée applicative conservée après recréation, pas un sinistre hôte ou une restauration longue durée.

Le dashboard local `03-fleet.json` utilise les nouvelles gauges persistées `shieldtest_fleet_*_last` : origine cible sans credentials/path/query, couverture explicite et compteurs des résultats reçus. Il est postérieur à source-09 et reste à déployer avec une image qui expose ces séries. Les autres panneaux restent provisionnés et vérifiés sur le laboratoire actuel ; le nombre de dashboards live reste deux à cette étape.

## Incrément reçus HTTP

`04-receipts.json` affiche les vrais compteurs du journal cible, l’état de continuité du collecteur, la disponibilité du journal et l’âge du dernier relevé réussi. Les étiquettes campagne/run/Pod distinguent les sources ; l’absence de campagne ne devient pas un zéro ni un succès. L’exporteur conserve un maximum de 1 000 couples campagne/run et 3 004 séries, sans labels par IP source. Un journal absent, une ligne partielle, un remplacement d’inode ou une rupture reste explicitement incomplet.

Validation locale : `node --test deploy/benchmark/telemetry/metrics.test.mjs`, `promtool check config prometheus.yml`, `promtool test rules lab.rules.test.yml`. Le vérificateur de monitoring exige maintenant trois scrapes et quatre dashboards. La présence du dashboard Fleet n’établit pas la présence de ses gauges sur une ancienne image du contrôle. Une qualification de campagne reste distincte de ces contrôles de collecte.

Livraison ciblée : sauvegarder manifests/ConfigMaps et reçus éphémères actuels, vérifier l’absence de campagne, importer l’image telemetry immuable, ajouter seulement les politiques nécessaires, puis changer les références ConfigMap des déploiements monitoring existants. Conserver les PVC et toutes les autres images, identités et budgets ; ne pas appliquer globalement une ancienne release de base. Vérifier imageID, trois scrapes up, quatre dashboards, métriques du collecteur, historique inchangé et compteurs inconnus lorsqu’aucun run n’est observé. Retenir les anciens manifests pour rollback et conserver les reçus archivés sous leur ancienne identité de source.

Format d’exposition : [Prometheus text format](https://prometheus.io/docs/instrumenting/exposition_formats/). Le texte `/metrics` est fourni par le collecteur ; le JSON existant n’est pas scrapé comme du texte Prometheus.

Observation du 15 octobre : l’incrément est appliqué sur le lab, avec trois scrapes up et quatre dashboards. Image et preuve de conservation sont dans le [checkpoint](../../../docs/monitoring-receipts-checkpoint.json). Grafana sous son plafond CPU de 200m nécessite plus de 100 secondes pour son initialisation ; prévoir une attente opérateur de 300 secondes sans relâcher les contrôles de readiness. Les premiers délais trop courts et le retry sont documentés dans [current setup](../../../docs/current-setup.md). Les compteurs par campagne restent absents sans trafic étiqueté ; aucune campagne n’a été lancée pour cette recette.
