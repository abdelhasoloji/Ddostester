## Efficient execution rules

- Execute available work in sequence, announce material results and record the precise dependency for any remaining work. No intermediate approval is needed for the locally authorized work.
- Use targeted tests for the changed contract and the repository's applicable delivery gates. Run a given check again only after a related change/failure or a new environment justifies it.
- No repeated campaign, deployment or polling loop to force a pass. A diagnostic observation cannot become a qualified result by relabelling it.
- A poll/readiness check has a fixed timeout and purpose. Do not start a remote job or publish a workflow just to keep running after handoff.
- Report code delivered, checks actually executed, environment/source identity, runtime changes and the next lot. Do not turn remaining hardware/CI work into an unstated completion claim.
