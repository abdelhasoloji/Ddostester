## Efficiency workstream

### Increment 1 — fast commit gate and short loop

- `.githooks/pre-commit`: prettier + eslint on the staged files, then a full typecheck.
  Enabled `core.hooksPath .githooks` (it was configured by `npm prepare` but not active).
  `SKIP_TYPECHECK=1` for doc-only commits, `git commit --no-verify` in an emergency.
- `scripts/verify-touched.mjs` and `npm run verify:touched`: format/lint only on changed
  files, full typecheck, then `vitest --changed` in both workspaces.

Why: two CI runs this week were red on issues a 20-second hook catches — prettier on files
I never opened, and a mock type intersection. The loop between edits was 4 minutes, which
encouraged skipping it.

Measured: the hook adds ~25 s to a commit; `verify:touched` is seconds when one module
changes, and falls back to the full suite when a shared file like `package.json` changes
(vitest treats every test as affected, which is correct).

### Increment 2 — the DRS loop runs in CI

`scripts/qa/drs-e2e.mjs` builds a frozen measured plan and drives the real orchestrator,
generator and probe collector against a loopback target: 15 s, no database, no build step.
It asserts FINAL_REPORT, at least one sealed proof, a PARTIAL assessment and the
generator+user evidence points. `npm run test:drs` runs it and CI gained a `drs-e2e` job.
Verified green on the PR (drs-e2e pass) and merged as #254.

### Increment 3 — pre-push stops duplicating CI

The hook ran `verify:fast` on every push: lint, typecheck and both suites, four to five
minutes, for work CI repeats five minutes later. With the pre-commit gate in place, pre-push
now runs the repository-wide lint and typecheck only (~30 s) and leaves the suites to CI.
`PRE_PUSH_FULL=1` keeps the old behaviour.

Measured: a push now costs about 30 s instead of 4–5 minutes, in a session that pushed
eighteen times.

### Increment 4 — the client report as a PDF

`scripts/operations/drs-report-pdf.mjs` turns the JSON report into the document a client
keeps: verdict and status, scope, the level table, the archived requirements the fleet did
not reach (highlighted), the reservations and the evidence hashes. `npm run report:pdf`
fronts it.

Verified against the report of a real measured run: two A4 pages, gaps legible, no
decoration. Playwright pins its bundled browser to its own release, so the script prefers the
installed Chrome and falls back to `CHROME_PATH`.

### Increment 5 — a browser I can drive with one command

UI verification needed a manual Chrome launch and a throwaway Playwright script each time.
`scripts/operations/browser.mjs` starts (or reuses) a dedicated profile with the DevTools port
open, and `--close` stops it. The profile persists, so the client certificate and the session
survive a service restart.

Verified the launch path on a scratch profile and port (9333), the reuse path, and the close
path (port 9333 stopped answering afterwards). It defaults to 9222 and the production URL.

### Increment 6 — a staging instance on its own database

`ddostester-staging.service` runs on `127.0.0.1:8081` from its own checkout
(`/home/shieldtest/ddostester-staging`) against `ddostester_staging`; environment and login
live in `/etc/ddostester-staging.env` and `/root/.ddostester-staging-login` (both 0600).
`deploy/staging-update.sh` fetches main, builds, applies the account migration, restarts and
waits for `/health`.

Two things bit on the way, both worth recording:

- the app refuses to start in single mode before `migrate-users --apply`, so a fresh staging
  database needs that one command;
- `. /etc/ddostester-staging.env` strips the JSON quotes from `AUTH_USERS`, and systemd's
  EnvironmentFile does the same. The value must be single-quoted in the file:
  `AUTH_USERS='[{...}]'`.

Verified: service active, `/health` 200, `userMode=single`, `authRequired=true`, build 502.
Public exposure waits on one DNS record (`drs-staging.trustena.lu → 31.31.74.228`); the
Caddy block and the exact procedure are in `docs/product/staging.md`.
